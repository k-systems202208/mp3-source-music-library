# 起動時オーナー認証の安定化 v2.7.4

## 症状

Windows版Chromeで、アプリ起動直後の次のURLが黒い読み込み画面のまま残ることがありました。

```text
/api/local-auth/exchange?token=...
```

タブを閉じ、管理画面の「ブラウザで開く」を押すと正常に開けるため、サーバーやDBではなく最初の認証引き渡しが原因でした。

## 原因と方針

本文なしのHTTP 303だけに依存した起動遷移が、一部環境で読み込み中として残る可能性がありました。Cookie交換の安全性を維持しつつ、明示的なHTML引き渡しへ変更しました。

## 実装

- ワンタイムトークンを1回だけ消費
- ローカルオーナーCookieを発行
- `location.replace`で即時遷移
- meta refreshを予備として追加
- 手動リンクを表示
- 500ms後の予備遷移
- `Connection: close`
- CSP
- `X-Frame-Options: DENY`
- 認証トークンをHTML本文へ含めない
- `next`は許可されたローカルパスだけ

## 実機結果

RC1で2回再現後、RC2を上書きし、アプリ完全終了→起動を3回連続で確認しました。3回とも認証交換URLで停止せずライブラリ画面へ遷移しました。

## 回帰

v2.7.5でも次を継続しています。

- ローカルオーナー認証
- 起動認証の繰り返し引き渡し
- PWA静的配信と安全なstartup handoff
- Tailscale利用者識別
