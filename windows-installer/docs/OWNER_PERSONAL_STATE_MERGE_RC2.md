# v2.7.0 RC2 オーナー個人状態統合仕様

## 対象

ローカルオーナーと、オーナー本人のTailscale利用者プロフィールを関連付ける際、
Tailscale側プロフィールに既存の`user_track_state`がある場合を対象とします。

## 統合ルール

| 項目 | ルール |
|---|---|
| 再生回数 | オーナー側＋Tailscale側 |
| 最終再生日時 | ISO日時を比較して新しい方 |
| お気に入り | 論理OR。どちらかが1なら1 |
| 評価 | 片方がNULLなら設定済み側。同値なら維持。異値なら全処理中止 |
| created_at | 同一曲が両側にある場合は既存オーナー行を維持 |
| updated_at | 統合実行日時 |

## 安全境界

1. 候補利用者とTailscaleログイン名を再照合
2. 候補利用者が有効であることを確認
3. 候補プロフィールの識別情報が1件だけであることを確認
4. 全評価競合と日時の解釈可否を変更前に検査
5. 個人状態を統合
6. Tailscale識別情報をオーナーへ移動
7. 空になった候補プロフィールを削除
8. `PRAGMA foreign_key_check`を実行
9. 失敗時はトランザクション全体をロールバック

関連付け開始前には`library-pre-owner-link-*.db`を作成します。

## 画面

承認前に次を表示します。

```text
個人状態 N曲・再生 N回・お気に入り N件・評価 N件
```

評価競合がある場合は承認ボタンを無効化し、件数を表示します。
バックエンドでも再検査するため、画面表示後に状態が変わっても安全側で停止します。
