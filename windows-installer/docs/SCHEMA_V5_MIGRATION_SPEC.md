# スキーマ5移行仕様（v2.7.0 第1工程）

この工程では、ユーザー画面・お気に入りボタン・Tailscaleユーザー判定は追加しません。

## 追加するもの

- `users`
- `user_identities`
- `user_track_state`
- 移行直前専用バックアップ
- スキーマ4から5へのトランザクション移行
- 既存の曲状態をオーナーへコピーする処理
- 移行の再実行防止と整合性確認

## 移行前バックアップ

既存データベースがスキーマ5未満の場合、接続前に次を作成します。

```text
Backups/library-pre-v2.7.0-YYYYMMDD-HHMMSS.db
```

SQLite Backup APIで複製し、`PRAGMA quick_check`、スキーマバージョン、曲数を照合します。バックアップの作成・検証に失敗した場合、移行処理は開始しません。

## 既存状態の移行

`tracks`の次の値をオーナーの`user_track_state`へコピーします。

```text
favorite
rating
play_count
last_played_at
```

すべて初期値の曲は状態行を作りません。`rating=0`は未設定ではなく有効な値として移行します。利用不可の曲も状態を保持します。

## 安全性

テーブル作成、オーナー作成、状態移行、検証、スキーマバージョン更新を1つのトランザクションで処理します。途中で失敗した場合は全体をロールバックします。

旧`tracks`列はこの工程では削除せず、値も変更しません。この開発パッケージは実DBへ適用せず、仮データベースの回帰テスト専用です。
