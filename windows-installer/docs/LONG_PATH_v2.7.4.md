# Windows長パス対応 v2.7.4

## 背景

従来、Windowsの絶対パスが260文字以上になるMP3で、走査・タグ解析・再生に失敗するケースがありました。ファイル自体は正常で、Windows側のパス表現が原因でした。

## 実装

`src/long_paths.py`で、WindowsのファイルI/O境界だけ拡張長パスへ変換します。

- ローカル: `\\?\C:\...`
- UNC: `\\?\UNC\server\share\...`

対象:

- 再帰走査
- 存在確認、`stat`
- 読み込み、シーク
- ID3・音声情報
- 外部・埋め込みアートワーク
- 内容署名
- MP3 HTTP Range配信

## DB・API

SQLiteには音楽ルートからの通常の相対パスを保存します。`\\?\`表現はDB、JSON、HTMLへ保存・表示しません。既存曲ID、移動検出、URL互換性を維持します。

## 実機結果

- 長いパス: 201曲
- 読み取り・シーク: 201／201
- 失敗: 0
- 最長絶対パス: 364文字
- 複製DBフルスキャン: 8,480／8,480
- 以前の読込エラー201件: 解消
- HTTP Rangeサンプル: 3曲合格
- 実運用DB・MP3: 検証工程では変更なし

## 回帰

v2.7.5でも長パス試験、読み取り専用プローブ、複製DBフルスキャンを継続しています。

## 非対応

- MP3名やフォルダー名の自動短縮
- タグの書換え
- Windows以外で不要な`\\?\`付与
- OS・ファイルシステム自体が拒否する不正名
