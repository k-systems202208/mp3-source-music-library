# v2.7.1 工程3 新版通知

## 目的

GitHubで新しい公開済みReleaseが作成されたことを、オーナーへ安全に案内します。
音楽ライブラリの起動、検索、再生はGitHubへの接続結果に依存させません。

## 表示対象

- ローカルオーナー
- オーナーへ関連付け済みのTailscale本人

一般利用者および未識別利用者には表示しません。

## 機能

- GitHubの公開済みRelease一覧を確認（プレリリース設定を含む）
- 下書きを除外し、最も新しいセマンティックバージョンを選択
- ホーム画面上部の新版通知
- オーナー画面内の新版通知欄
- 現在版、最新版、公開日時の表示
- 対象リポジトリのReleaseページを開く導線
- 「後で」による同一バージョン通知のブラウザ単位での非表示
- 「今すぐ確認」によるキャッシュを使わない再確認
- 手動確認後の完了メッセージと確認時刻の表示
- 成功結果の24時間キャッシュ
- 通信失敗時の前回成功結果利用

## 安全設計

- 自動ダウンロード、自動インストール、自動更新は行いません。
- Release URLはHTTPSかつ対象GitHubリポジトリ配下だけを許可します。
- GitHubの下書きReleaseは通知対象にしません。
- 通信失敗は非致命エラーとして扱います。
- GitHubへの通常確認は1日1回です。

## バージョン管理

工程3のmain統合時点では、公開済みv2.7.0との整合性を維持します。
`src/update_check.py`の`CURRENT_VERSION`、サーバー識別子、アプリ本体、
インストーラーの各バージョンは、v2.7.1 RC作成工程で一括して2.7.1へ更新します。

## 試験

`tests/test_update_notification.py`で次を確認します。

- セマンティックバージョン比較
- プレリリースだけが存在する公開リポジトリでの最新版選択
- 下書き・不正なタグの除外
- Release URL検証
- キャッシュおよび強制再確認
- オフライン時の非致命動作
- オーナー専用API
- プレビュー用模擬通知
- フロントエンドの通知、後で、手動確認完了表示

## RC1実機確認による修正

公開済みv2.6.1からv2.7.0までのReleaseは、GitHub上ですべて`prerelease=true`でした。GitHubの`/releases/latest`はプレリリースを対象にしないためHTTP 404となりました。RC2では`/releases?per_page=100`を使用し、公開済みRelease一覧から最新バージョンを選択します。
