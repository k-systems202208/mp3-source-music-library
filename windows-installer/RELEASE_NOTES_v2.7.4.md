# 自宅音楽ライブラリ v2.7.4

v2.7.4では、Windowsの従来のパス長制限により読み込めなかった、深いフォルダーや長いファイル名のMP3へ対応しました。

## 長いファイルパス対応

- 260文字以上のローカルファイルパスに対応
- UNCネットワークパスの長いパス形式に対応
- 再帰走査、ファイルサイズ、先頭・末尾読込、シークを長いパス対応
- ID3タグとMutagen音声情報の取得を長いパス対応
- 埋め込み・外部アートワークの取得を長いパス対応
- 移動検出用の内容署名を長いパス対応
- MP3のHTTP配信とRange指定による途中位置再生を長いパス対応

Windows内部でファイルを開くときだけ長いパス形式を使用します。SQLiteには従来どおり通常の相対パスを保存し、MP3、タグ、ファイル名、フォルダー名は変更しません。

## 起動時オーナー認証の安定化

RC1のWindows実機確認で、アプリ再起動直後に自動表示されるローカルオーナー認証URLが、Chrome上で黒い読み込み画面のまま停止する現象を確認しました。

RC2では、Cookie発行後の本文なしリダイレクトだけに依存せず、次の認証完了ページを返す方式へ変更しました。

- JavaScriptによる即時遷移
- meta refreshによる予備の遷移
- 画面が切り替わらない場合の手動リンク
- 接続の明示的な終了
- ワンタイムトークンをHTML本文へ出力しない安全設計

アプリ終了・再起動を3回連続で行い、毎回ライブラリ画面まで正常に進むことを実機確認しています。

## 実機・実データ検証

- 音楽フォルダー内MP3：8,480曲
- 従来の登録曲：8,279曲
- 長いパスにより未登録だった曲：201曲
- v2.7.4実運用DBへの登録：8,480曲
- 長いパス201曲の登録：201曲
- スキャンエラー：0件
- アートワーク：7,708曲
- 最長パス：364文字
- 長いパスの実ファイル3曲で先頭・中間位置のHTTP範囲再生に合格
- 最長364文字の曲をPCブラウザで再生・シーク
- 既存曲ID、利用者、お気に入り、再生状態、スキン設定を維持

Tailscale接続とスマートフォンPWAはv2.7.3の既存機能を維持し、回帰試験に合格しています。今回の実機報告では、長いパス曲のスマートフォン再生は個別の確認結果を記録していません。

## 更新方法

自宅音楽ライブラリを終了し、`MusicLibrary-Setup-2.7.4-x64.exe`を実行します。v2.7.3をアンインストールする必要はありません。

曲、利用者、お気に入り、再生履歴、スキン、バックアップ、Tailscale設定、スマートフォンのホーム画面利用は維持されます。DBスキーマはv6のままです。
