# 自宅音楽ライブラリ v2.7.4

v2.7.4では、Windowsの従来のパス長制限により読み込めなかった、深いフォルダーや長いファイル名のMP3へ対応します。

## 改善内容

- 260文字以上のローカルファイルパスに対応
- UNCネットワークパスの長いパス形式に対応
- 再帰走査、ファイルサイズ、先頭・末尾読込、シークを長いパス対応
- ID3タグとMutagen音声情報の取得を長いパス対応
- 埋め込み・外部アートワークの取得を長いパス対応
- 移動検出用の内容署名を長いパス対応
- MP3のHTTP配信とRange指定による途中位置再生を長いパス対応

## 実機検証結果

- 音楽フォルダー内MP3：8,480曲
- 従来の登録曲：8,279曲
- 長いパスにより未登録だった曲：201曲
- v2.7.4複製DBへの登録：8,480曲
- 長いパス201曲の登録：201曲
- スキャンエラー：0件
- 最長パス：364文字
- 長いパスの実ファイル3曲で先頭・中間位置のHTTP範囲再生に合格
- 既存曲ID、利用者、お気に入り、再生状態、スキン設定を維持

## データ互換性

Windows内部でファイルを開く時だけ長いパス形式を使用します。SQLiteには従来どおり通常の相対パスを保存するため、既存DBとの互換性を維持します。DBスキーマはv6から変更しません。

## 更新方法

v2.7.3をアンインストールせず、`MusicLibrary-Setup-2.7.4-x64.exe`を上書きインストールします。初回起動時のスキャン完了後、従来未登録だった201曲が追加されます。

曲、利用者、お気に入り、再生履歴、スキン、バックアップ、Tailscale設定、スマートフォンのホーム画面利用は維持されます。
## RC2で修正した起動時の認証遷移

RC1のWindows実機確認で、アプリ再起動直後に自動表示されるローカルオーナー認証URLが、Chrome上で黒い読み込み画面のまま停止する現象を確認しました。管理画面から開き直すと正常になるため、ライブラリ本体ではなく最初の認証完了レスポンスの遷移方式を修正しています。

RC2では、本文なしの303リダイレクトだけに依存せず、Cookie発行後にJavaScript、meta refresh、手動リンクでライブラリ画面へ進む認証完了ページを返します。接続も明示的に閉じ、ワンタイムトークンはページ本文へ出力しません。
