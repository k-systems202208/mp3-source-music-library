# 運用・セキュリティ

## 推奨構成

- Windows PC上で自宅音楽ライブラリを実行
- サーバーはlocalhostへバインド
- 同一PCはローカルURLで利用
- 外部端末はTailscale ServeのHTTPS URLで利用
- ルーターのポート開放、DMZ、Funnelは使用しない

## 利用者境界

| 種別 | できること |
|---|---|
| ローカルオーナー | 全機能、利用者停止・再開、バックアップ・復元、関連付け承認 |
| Tailscaleオーナー | 個人機能、オーナー向け閲覧。一部のローカル限定管理は不可 |
| Tailscale利用者 | 自分の履歴、お気に入り、スキン、プレイリスト |
| 匿名 | 検索・再生。個人状態保存なし |

オーナー自身は停止できません。他利用者は完全削除せず、停止・再開で管理します。

## 認証

### ローカルオーナー

- ランチャーがcontrol secretでワンタイムトークンを登録
- トークンは短時間・1回限り
- ブラウザがCookieへ交換
- Cookieは`HttpOnly`、`SameSite=Strict`
- 認証交換ページはCSPとframe拒否を設定
- URLの`next`は許可されたローカルパスだけ

### Tailscale

- 利用者ヘッダーを無条件には信頼しない
- localhostのTailscale Serve中継という前提を検査
- 表示名ではなく安定したsubjectで識別
- 重複値、制御文字、不正URLを拒否

## データ保護

- DB、バックアップ、設定、ログを静的配信しない
- API応答をPWAキャッシュへ保存しない
- MP3とアートワークをService Workerへ保存しない
- プレイリスト操作時に所有者をサーバー側で検証
- SQLはパラメーター化
- 外部キーとトランザクションを有効化
- 更新前にDBバックアップを作成

## PWA

PWAはアプリストア型の完全オフラインアプリではありません。キャッシュするのはHTML、manifest、アイコン、offline案内等の画面シェルです。認証状態はブラウザCookie、個人データはサーバーDBが正本です。

端末紛失時はTailscale側で端末を無効化し、必要に応じて利用者をアプリ側でも停止します。

## バックアップ運用

- 大きな更新前に手動バックアップ
- 自動移行前バックアップの存在を確認
- バックアップは定期的に別ドライブへ複製
- 復元対象と作成日時を確認
- MP3は別途ファイルバックアップが必要
- `library.db`だけで音源は復元できない

## ログ・共有時の注意

共有前に次を確認します。

- Tailscale URL・ホスト名
- Windowsユーザー名
- 音楽フォルダーの実パス
- 曲名や個人情報
- 認証トークンを含むURL
- GitHubトークン等の秘密情報

ワンタイム認証URLのスクリーンショットやログを公開場所へ貼らないでください。

## 更新運用

1. 現在版でバックアップ
2. アプリを完全終了
3. SHA-256を確認
4. 上書きインストール
5. バージョン、曲数、利用者状態を確認
6. 起動認証、再生、シーク、PWAを確認
7. DB移行後の自動バックアップを確認

## インターネット一般公開を避ける理由

本アプリは家庭内・個人Tailscale利用を前提とし、公開サービス向けのアカウント登録、パスワードリセット、レート制限、監査基盤、法的配信管理を備えていません。公開Webサーバーとして運用しないでください。
