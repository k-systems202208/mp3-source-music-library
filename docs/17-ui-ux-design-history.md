# UI／UX設計の変遷

## 1. カード目録

初期版から、曲を図書館のカードのように並べるデザインを採用しました。装飾より曲名・アルバム・アーティストの読みやすさを優先しています。

## 2. 3ビューとドリルダウン

- 曲
- アーティスト
- アルバム

アーティスト→アルバム→曲の流れをパンくずで示し、現在の文脈を失わないようにしました。

## 3. 表記補正

ローマ字や文字化けを自動で正式表記と断定せず、元値を残したまま利用者が補正します。検索で正式表記を調べる導線を用意し、確認可能性を優先しました。

## 4. プレーヤー

一覧の再生操作から、アートワークを大きく表示するプレーヤーへ発展しました。シャッフル、リピート、シークを追加しています。

## 5. Windows管理画面

Pythonや黒いコンソールを利用者へ意識させないため、次をGUIへ集約しました。

- 音楽フォルダ選択
- 開始・停止
- ブラウザ起動
- データ保存先
- Tailscale外部接続

## 6. v2.7.0の現在利用者チップ

右上へ現在利用者を常時表示しました。再生回数と★が誰に保存されるかを操作前に分かるようにするためです。

表示例:

```text
オーナー（オーナー）
家族A
利用者未確認
```

匿名時は★を無効化し、保存されない理由をツールチップで説明します。

## 7. 利用者モーダル

一つのモーダルに次を集約しました。

- 現在の利用者
- 識別元
- Tailscale関連付け
- 利用者一覧
- 利用停止・再開

通常利用者には不要な管理機能を常時画面へ出さず、右上から必要時だけ開く構成です。

## 8. オーナー関連付けUI

誤昇格を防ぐため、ワンタップ統合ではなく段階表示にしました。

1. ローカルでコード発行
2. Tailscale側で送信
3. 候補の表示名・ログイン名
4. 個人状態の件数
5. ローカルで承認

評価競合がある場合は承認ボタンを無効化し、バックエンドでも再検査します。

## 9. 利用者管理UI

完全削除ではなく「利用を停止」「利用を再開」と表示します。履歴を誤って失う操作に見えないよう、状態変更の意味を限定しました。

Tailscale経由オーナーには一覧を見せますが、変更ボタンはローカルオーナーに限定します。

## 10. お気に入り

曲カードの☆／★は現在利用者の状態です。サーバーへ「反転」ではなく`true`／`false`を送ることで、通信再試行による二重反転を防ぎます。

## 11. 今後のUI課題

- 長いパスの診断を分かりやすく表示
- 評価UI
- プレイリスト
- 利用者表示名編集
- 管理・診断機能の整理
- スマートフォンでのモーダル操作改善
