# note投稿原稿案 — v2.7.0追補

## タイトル案

家族で使っても再生回数を混ぜない――自宅音楽ライブラリv2.7.0の利用者識別設計

## 本文

自宅のMP3をWindows PCから配信し、PC・スマートフォン・外出先のブラウザで再生できる「自宅音楽ライブラリ」をv2.7.0へ更新しました。

今回の中心は、家族で同じライブラリを使っても、再生回数とお気に入りを利用者ごとに分けることです。

### なぜ単純なアカウント選択にしなかったか

ブラウザに利用者名のプルダウンを置くだけなら簡単です。しかし、誰でも「オーナー」を選べてしまうと、利用者管理や個人状態の境界になりません。

そこで接続経路ごとに識別方法を分けました。

```text
自宅PCの管理画面
  → 短時間の一時トークン
  → オーナー用Cookie

Tailscale Serve
  → Tailscaleが付与する利用者情報
  → 利用者プロフィール

どちらでもない接続
  → 匿名
```

匿名でも検索と再生はできますが、再生回数やお気に入りは保存しません。誰か分からない状態で、推測して別の人へ記録するより安全だからです。

### DBスキーマ5

SQLiteへ次の3テーブルを追加しました。

```text
users
  利用者プロフィール、オーナー、利用停止

user_identities
  local_owner／Tailscaleの識別情報

user_track_state
  利用者×曲ごとの再生回数、お気に入り、評価
```

旧版の共通再生回数とお気に入りは、初回起動時にオーナーへ移行します。移行前にはDBをバックアップし、件数、値、外部キーを検査します。途中で失敗すればロールバックします。

### 自宅PCと本人のTailscaleを同じオーナーにする

同じ本人でも、自宅PCではローカルオーナー、外出先ではTailscale利用者として最初は別プロフィールになります。

自動で統合しないのは、家族のTailscaleアカウントを誤ってオーナーにしないためです。

1. 自宅PCで一時コードを発行
2. 本人のTailscale画面からコードを送信
3. 自宅PCに表示名・ログイン名・個人状態件数を表示
4. 本人だと確認して承認

すでに両側で曲を聴いていた場合も、状態を失わず統合します。

```text
再生回数      合算
最終再生日時  新しい方
お気に入り    どちらかが★なら★
評価          競合がなければ統合
```

異なる評価が両側にある場合は、勝手に決めず処理を中止します。

### 利用者管理は最小限

オーナーは利用者一覧を確認し、家族利用者を停止・再開できます。完全削除にしなかったのは、誤操作で再生履歴やお気に入りを消さないためです。

変更操作は自宅PCのローカルオーナーだけに限定しました。外出先のTailscaleオーナーは一覧を見られますが、利用停止はできません。

### 今後

v2.7.0で利用者別の再生回数とお気に入りまで実装できました。次の候補はプレイリスト、評価UI、長いWindowsパスへの対応、FLAC等の形式対応です。

ソースコード、設計書、API、DBスキーマ、利用マニュアルはGitHubで公開しています。ただし、MP3音源、実DB、利用者情報、Tailscale URLは含めていません。
