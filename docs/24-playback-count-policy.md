# 再生回数の記録仕様

対象: 自宅音楽ライブラリ v2.7.7 以降の互換動作
正規実装: `windows-installer/src/music-library-search.html`、`windows-installer/src/server.py`、`windows-installer/src/database.py`

## 1. 再生1回の定義

再生回数は、ブラウザが対象曲を新しくプレーヤーへロードし、`HTMLAudioElement.play()` が正常に開始できた時点で1回として記録する。

これは「曲を最後まで再生した回数」ではない。再生時間、再生割合、曲末到達は記録条件に含めない。

## 2. 同一ロード内の扱い

- 新しい曲をロードして再生開始に成功したとき: 1回加算する。
- 同じロードのまま一時停止し、再開したとき: 追加加算しない。
- 別の曲へ移動後、同じ曲をあらためてロードして再生したとき: 新しい再生として1回加算する。
- 1曲リピートで曲末後に再度先頭から再生したとき: 新しい再生として1回加算する。
- `play()` が失敗したとき: 加算しない。

画面側は1ロードにつき1回だけ `/api/tracks/{id}/played` を送るため、同一ロード内の一時停止・再開では重複記録しない。

## 3. 利用者ごとの扱い

- 認証済み利用者: `user_track_state` の本人行へ再生回数と最終再生日時を保存する。
- ローカルオーナーとTailscale利用者: それぞれ解決された現在利用者IDへ保存する。
- 匿名利用者: 音楽再生は可能だが、個人別再生回数と最終再生日時は保存しない。
- 停止中の利用者: 個人状態の更新を許可しない。

クライアントから利用者IDを受け取ってはならない。現在利用者はサーバーがCookieまたはTailscale identityから決定する。

## 4. APIの意味

`POST /api/tracks/{id}/played` は「ブラウザ側で再生開始が成立したことを記録する」APIとして扱う。

APIが呼ばれた時点で、サーバーは曲末到達や再生秒数を再判定しない。再生条件を将来変更する場合は、画面側の記録タイミング、API仕様、回帰テストを同時に変更する。

## 5. 互換性方針

v2.7.7の実動作を互換仕様として維持する。単にコメント上の「再生完了」表現に合わせるため、曲末到達時まで記録を遅延させる変更は行わない。

再生回数の意味を「30秒以上」「50%以上」「最後まで」等へ変更する場合は、既存統計の意味が変わるため、通常の不具合修正ではなく仕様変更として扱う。
