# プロジェクトの起点と要件

## 起点

iTunesからエクスポートしたXMLに含まれる音楽を、費用をかけずブラウザで検索する静的アプリとして開始しました。その後、MP3を正本とする構成、アートワーク、SQLite API、Windowsインストーラー、家庭内・Tailscale利用、利用者別状態へ段階的に発展しました。

## 現行の目的

- 手元のMP3を移動・再エンコードせず検索・再生する
- 家庭内の複数端末から同じライブラリを使う
- 利用者ごとの履歴、お気に入り、見た目、プレイリストを分離する
- Windows利用者が管理画面とインストーラーで運用できる
- 外部公開用のサーバー管理を要求せず、Tailscale内に閉じる
- DB障害や更新失敗から復旧できる

## 主要要件

| ID | 要件 |
|---|---|
| R-01 | MP3ファイルを音声の正本とする |
| R-02 | 曲名、アーティスト、アルバム、作曲者を検索できる |
| R-03 | ブラウザで再生、シーク、連続再生できる |
| R-04 | アートワークを表示できる |
| R-05 | 文字化けや欠損タグを可能な範囲で補正できる |
| R-06 | 曲の移動・改名を検出し、既存IDを維持する |
| R-07 | 利用者別の再生状態・お気に入りを保存する |
| R-08 | 利用者別スキンを保存する |
| R-09 | 利用者別プレイリストを保存する |
| R-10 | ローカルオーナーとTailscale利用者を安全に識別する |
| R-11 | DBをバックアップ・復元できる |
| R-12 | Windowsの長いファイルパスを扱える |
| R-13 | スマートフォンのホーム画面から起動できる |
| R-14 | 更新の存在を通知し、自動更新は行わない |
| R-15 | MP3、DB、認証情報をPWAキャッシュへ保存しない |

## 非目標

- 音楽配信サービスとの同期
- DRM解除
- MP3の編集、タグ書戻し、再エンコード
- インターネット一般公開
- App Store／Google Play配布
- オフラインMP3再生
- プレイリストの共同編集・外部形式入出力

## 設計原則

1. 音源を破壊しない
2. 利用者データをインストール先から分離する
3. 更新前にDBバックアップを作る
4. 匿名接続に個人状態を書き込ませない
5. 接続元・利用者・所有権をサーバー側で検証する
6. 失敗時は推測で継続せず、安全に停止する
7. 履歴文書と現行仕様を区別する
